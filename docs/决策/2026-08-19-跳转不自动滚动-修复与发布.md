# 决策：dsh-chat-rail 跳转不自动滚动 bug 的处理与发布

日期：2026-08-19
状态：已完成（npm 0.1.1 已发布，2026-08-19T15:10Z）

## 一、问题

用户报告：点击较靠前的节点时正常触发"加载中"，但加载完成后没有自动跳过去。

## 二、诊断结论

1. **根因已修复**：commit `9a8bc01`（2026-08-19 20:25）已针对此问题修复——`jumpToMessage` 翻页加载完成后轮询等待目标 DOM 行渲染（50ms×100 次≈5s 超时）再 `scrollIntoView`，修复"多页加载后需二次点击"。
2. **用户环境是旧版**：DSH profile `C:\Users\MaxNull\.dsh\profiles\ssid\node_modules\@max-null\dsh-chat-rail` 安装的是 npm **0.1.0**（发布于 0.1.0 时点 2026-08-18T20:03Z，早于修复提交），非符号链接。用户跑的是修复前行为。
3. **运行时事实已验证**（阅读 DSH 源码）：
   - rail 重构 key `'13:input-message' + id` 与 `conversationContextKey('input-message', id)` = `kind.length:kind+id` **一致**，`chat.nodes.get(key)` 能命中；
   - `getSnapshot()` 每次调用 `ensureFresh()`，翻页后快照必新；
   - `loadOlder` 完成时 `conversation.prepend` 同步更新 inputs/contexts，flush 在微任务中先于 `await` 恢复执行，节点 materialize 时序正确；
   - 9a8bc01 的 DOM 轮询逻辑正确。
4. **残余健壮性问题**（9a8bc01 提交信息自列"待后续优化"）：
   - guard 120 次耗尽后无"是否找到"检查，直接进入 5s DOM 轮询空转后失败；
   - 跳转失败静默返回 false，无日志上下文；
   - jumpToMessage 异步循环无取消机制，卸载后最长空转 ~5s。

## 三、处理方案

1. 增强 `jumpToMessage`：guard 耗尽快速失败（loaded 标记 + console.warn）、AbortSignal 取消机制（组件卸载/二次点击时中止）。
2. 跑测试（`pnpm test` 9/9 通过）+ typecheck 通过 + 构建（`pnpm build` 生成 lib/client.js）。
3. 提交 `2c9a47b` 推送 main，版本升 **0.1.1**，GitHub tag `v0.1.1` 已推送。
4. **npm 0.1.1 已发布**（2026-08-19T15:10:28Z，latest=0.1.1），npm 版本与 GitHub tag 对齐。
5. 待办：用户 DSH profile（`C:\Users\MaxNull\.dsh\profiles\ssid`）更新插件到 0.1.1 后生效。
