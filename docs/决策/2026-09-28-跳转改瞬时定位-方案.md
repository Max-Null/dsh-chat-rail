# 方案：跳转由「平滑滚动 + 多轮等待」改为「瞬时定位」

日期：2026-09-28
状态：**待审（方案，未实施）**
触发：用户实机观察——「滚动跳转动画效果还行，但跨度较大时要加载大量 DOM，实际效果不如原生导航条直接调转」

## 一、问题

点击侧栏较早的条目时，跳转的**体感**明显劣于 DSH 自带的 TurnNavigator：跨度越大越明显，感觉像在「飞过去」，且期间界面在忙。

## 二、现状对照（读源码，非推测）

背景：chat-rail 取代了官方 TurnNavigator 的侧栏入口（见 `docs/验证记录-2026-08-30-屏蔽官方TurnNavigator.md`），但**并未继承它的落位方式**——这正是本方案的由来。

| | 原生 TurnNavigator | chat-rail 当前实现 |
|---|---|---|
| 落位 | `scroller.scrollTop = top`，**瞬时赋值**<br>`ui-chat/src/client/chat/use-chat-viewport.ts:412` | `scrollTo({ behavior: 'smooth' })`，**平滑动画**<br>`src/client/index.tsx:1263` |
| 调度 | `loadThrough(seq).then(settle → requestAnimationFrame → reconcile)`<br>`ui-chat/src/client/chat/use-chat-navigation.ts:170-183` | 等几何安静（`quiet < 30` × `delay(150)`）→ 落位 → 复核 4 × `delay(600)`<br>`src/client/index.tsx:1274-1292` |
| 对抗分页补偿 | `beginPreserving(position)` + `reading.acceptNavigation(landing)`<br>`use-chat-navigation.ts:152-168` | 靠**等待**与**多轮复核**把位置拽回来 |
| 加载机制 | `session.loadThrough(seq)`<br>`use-chat-navigation.ts:182` | **同一个** `session.loadThrough(targetSeq)`<br>`src/client/index.tsx:1162-1177` |

**结论：加载那块两边一致**（都用 `loadThrough`，都是每页 200 条），所以「要加载大量 DOM」不是差异项；差异在**滚动方式**与**调度节奏**：

- 最坏情况 chat-rail 要 **4.5 秒等安静（30×150ms）+ 2.4 秒复核（4×600ms）**，中间还夹一次平滑滚动；
- 跨度越大 → 加载的 DOM 越多 → 重排越贵 → smooth 动画越拖；
- 原生在 `loadThrough` 返回后**一帧**就瞬时落位，没有长等待。

## 三、为什么要改

1. **体感**：瞬时定位在长会话、大跨度下明显优于平滑滚动——原生已经验证过这条路径。
2. **简化**：那套等待/复核是为了对抗「分页后 scrollIntoView 被拉回」（见 `index.tsx:1243-1248` 注释记录实测 145971 → 44464 snap-back）。原生只用一帧就落位，说明**补偿在 `loadThrough` 返回时已经结束**；我们不必用秒级等待去猜它什么时候结束。
3. **与官方行为一致**，减少后续内核升级时的适配面。

## 四、方案（三处改动，只动落位与节奏）

1. **落位改瞬时**：`scrollToRow()` 默认走 instant —— `scrollTo({ behavior: 'auto' })`，或直接赋 `scrollport.scrollTop`（与原生完全一致）。
   **连带删掉 `reducedMotion`**（`index.tsx:1242`）：落位恒定瞬时候，它只剩 `index.tsx:1263` 一处用处，留着是死代码。本包 `tsconfig.json` **未开启** `noUnusedLocals`，所以不删不会编译失败——但仍要删。
2. **去掉「等几何安静」循环**：`index.tsx:1274-1282` 的 `while (quiet++ < 30)` 换成 **一次 `requestAnimationFrame`**（学 `use-chat-navigation.ts:176-180` 的做法）。
3. **复核从 4 次缩到 1 次**：保留 `index.tsx:1285-1292` 的单次校验，补偿若真仍在进行也能兜住。

**边界（不做的事）**：

- **不动 `loadThrough` 的加载逻辑**——DOM 加载量两边相同，改它无收益且风险高；
- **不动 `jumpToMessage` 的可寻址/降级路径**（`nodeKeyOf`、5 秒 poll、`return false`）；
- **不动 hover 展开画卷的平滑滚动**（`index.tsx:1780`，那是交互反馈，不是跳转）。

## 五、风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 落位被分页补偿拉回 | 原方案的三次等待就是为此而设 | 保留 1 次轻量复核；若实测仍被拉回，再补一次 rAF 重试 |
| 平滑→瞬时的手感变化 | 有人偏好动画 | `prefers-reduced-motion` 的**要求本来就不高于瞬时**（瞬时 ≤ 任何动画），因此改完是「该分支随之下线」而非「保留判断」；见方案 ① 的连带项 |
| 与文件头注释不一致 | `index.tsx:1243-1248` 的注释描述了「等安静」的理由 | 改动时同步改写该注释，不留过期说明 |

## 六、验证方式

1. `pnpm run typecheck` + `pnpm test`（当前基线 50/50）。
2. `pnpm run build` 重建 `lib/`。
3. **实机**：长会话（≥1000 事件）里点最早的几条，确认落位**瞬时到达**且不被拉回；对比原生 TurnNavigator 的手感。
4. 交付路径同 0.6.5：bump 版本 → 用户 `npm publish` → 改 `profile-template` 与 web profile 的 pin → 替换插件集实体 → 重启思灵。

**回退**：改动集中在 `jumpToMessage` 的落位段，`git revert` 单个提交即可；已发布的产物可从 tag `v0.6.5` 取回（`.dsh-tmp/chat-rail-0.6.4-backup*` 还留着一份更早的实体）。

**落地后的收尾**：实施并实机验证通过后，本文档改名为 `2026-09-28-跳转改瞬时定位-改造与发布.md`、状态改为「已完成」，与 `docs/决策/2026-08-19-跳转不自动滚动-修复与发布.md` 的先例一致。
