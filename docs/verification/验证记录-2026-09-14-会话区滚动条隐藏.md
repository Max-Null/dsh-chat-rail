# 验证记录：会话区滚动条隐藏（2026-09-14）

> 环境：SSiD dev（Electron 44.2.0 / SSiD 0.3.0，内核 `0.1.5-rc.2`，CDP 9222）
> 实体：`@max-null/dsh-chat-rail@0.6.2`（未发 npm，本改动并入 0.6.2）
> 触发：用户报告「导航条插件之前会屏蔽会话面板区的 Y 轴滚动条，现在又有了」

## 一、取证：不是插件回归

| 检查对象 | 结论 |
|---|---|
| chat-rail 全历史（`5357afa` 初始版 → `d8357c1` → `7c29b67` → `b4f6ca2` → 0.6.2） | 只有 `.crl_nav` / `.crl_list`（rail **自身**）的滚动条规则：初始版 4px 细条 → 0.6.1（`b4f6ca2`）起 `width:0` 隐藏。**从未注入会话区规则** |
| SSiD 内置插件（`seek-soul-in-darkness/plugins/`） | 无任何滚动条 CSS |
| 第三方插件（genui / better-sidebar / office） | 规则只作用于各自容器，不涉及会话区 |
| 官方内核 `dsh-v0.1.2-rc.1` → `dsh-v0.1.5-rc.2` | `scrollbar-gutter: stable` + ui-theme `scrollbar.css` 的 8px 滚动条样式**两版一致**；唯一差异：0.1.5 新增 `.scrollBody { margin-right: 2px }` 与 `::-webkit-scrollbar-track { margin: 2px }`（官方注释：*the bar sits 2px clear of the column's edge instead of flush against it*） |
| SSiD dev 实况诊断 | `[data-conversation-scroll]` 唯一（`280,78,998×726`）、`offsetWidth-clientWidth = 8`、`overflow-y: auto`、`scrollbar-width: auto`，**无任何插件规则作用于它** |

**归属**：会话区滚动条是 DSH 官方既有设计。用户记忆中的「被屏蔽」对应 rail 自身滚动条（0.6.1 修复）；观感变化来自 0.1.5 的 2px 偏移让 bar 从「贴着内容边缘」变为「独立一条」。

## 二、决定与实现（用户拍板）

用户选择：**在 chat-rail 内直接隐藏**（不做设置开关，作用范围 = 插件自身）。

`src/client/index.tsx` 主样式表新增：

```css
[data-conversation-scroll]::-webkit-scrollbar-thumb,
[data-conversation-scroll]::-webkit-scrollbar-thumb:hover { background: transparent }
```

三条边界（均有源码依据）：

1. **画透明，而非把滚动条压成 0 宽** —— 宽度归零会连带回收 `scrollbar-gutter: stable` 的 8px 槽位，内容区变宽、输入卡横移；官方无条件保留槽位正是为输入卡跨视图不位移（`ConversationRoot.module.css` gutter 注释 + `2026-08-04-composer-tab-gutter-reservation`）。track 官方本就透明，故只需 thumb 一条。
2. **不写 `scrollbar-width`** —— ui-theme/`scrollbar.css` 注释记录实测：非 `auto` 的 `scrollbar-width` 会让 Chromium 丢弃该元素全部 `::-webkit-scrollbar*` 规则。
3. **用官方契约锚点 `[data-conversation-scroll]`**，不依赖 CSS module hash。

### 验证边界（未覆盖）

- **Firefox 路径**：`@supports not selector(::-webkit-scrollbar)` 分支未覆盖（本插件交付环境为 Chromium/Electron）。
- 对照实验（对 `.scrollBody` 强制 `#ff0000 !important`）未在会话区检出红色，红像素反而出现在 `x 696..773, y 10..41`；页面仅一个 `[data-conversation-scroll]`，成因未定（疑 Chromium 对滚动条伪元素的 `!important` 覆盖行为）。最终判据不依赖该对照，而是 ①②③⑤ 四组独立证据。
- 视觉终判：待用户目视确认（用户表示稍后自行截图）。
