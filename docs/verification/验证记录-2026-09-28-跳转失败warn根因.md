# 验证记录：`jumpToMessage` 的 "not loaded after loadThrough" 告警根因（2026-09-28）

> 环境：SSiD 1.0.0 装版（内核 `0.1.7-rc.2`）
> 实体：`@max-null/dsh-chat-rail@0.6.5`（插件集实体）
> 触发：用户贴出实机控制台告警

## 一、现象

```
[chat-rail] jumpToMessage: node "13:input-message61e88938-…" not loaded after loadThrough(1504)
jumpToMessage @ index.tsx:1188
```

同一会话内复现多次（另一个 node id 配 `loadThrough(1136)`）。**是 `console.warn` + `return false`，不是抛错**——跳转静默失败，界面不崩。

## 二、取证

### 2.1 key 拼写正确（排除「硬编码 turn 号」的怀疑）

告警里的 key 形如 `13:input-message<uuid>`，一度疑似硬编码。实为 DSH 的 node key 格式：

```ts
// deepseek-harness/packages/client/ui-conversation/src/client/contract/conversation.ts:319
export function conversationContextKey(kind: string, id: string): string {
  return `${kind.length}:${kind}${id}`
}
```

`'input-message'.length === 13` → `13:input-message<id>` 正确。

**此结论与 `docs/决策/2026-08-19-跳转不自动滚动-修复与发布.md` §二.3 一致**——同一件事在 2026-08-19 已核查过一次。

### 2.2 `loadThrough` 的三条早退路径

```ts
// deepseek-harness/packages/api/session-controller/src/client/sessions/session.ts:429
if (this.openState !== 'open' || !this.hasMore || this.baseSeq <= seq) return Promise.resolve()
```

即：会话未 open、**历史已到底（`!hasMore`）**、**窗口已覆盖该 seq（`baseSeq <= seq`）** 三种情况立刻返回。chat-rail 在它返回后轮询节点 100 × 50ms，仍无节点即告警。

### 2.3 归属（推断，未实证）

**被压缩掉的历史消息不再产生 chat node。**

`messageDefinition.match` 要求事件仍是 append 型 surface 事件：

```ts
// deepseek-harness/packages/client/ui-chat/src/client/conversation-nodes/message.ts:67
return isAppendSurfaceEvent(event) && !isCompactionCheckpoint(event)
      ? { id: String(event.data.id), role: 'start' } : null
```

```ts
// deepseek-harness/packages/core/session/src/surface.ts:89
export function isAppendSurfaceEvent(event): event is SurfaceEvent & { surfaceOp: 'append' } {
  return isSurfaceEvent(event) && event.surfaceOp === 'append'
}
```

压缩以 surface **替换**（`surfaceOp !== 'append'`）遮蔽既有范围 → 那些 `user/message` 不再是 append → **不再建 chat node**。

而 chat-rail 的投影只按来源过滤，不感知 surface 状态：

```ts
// dsh-chat-rail/src/index.ts:132-135
if (event.type === 'user/message') {
  const data = event.data as { source?: { kind?: string } | null; … } | null
  if (… || data.source.kind !== 'user') { /* 排除 */ }
```

→ **「侧栏列得出、点了跳不过去」**。

**为什么投影侧拿不到修复手段**：投影 `apply` 收到的 event 只有 `{ type, seq, time, data }`（`src/index.ts:125`），**不含 `surfaceOp`**，无法在投影侧按 surface 状态过滤。

## 三、影响与结论

| 项 | 结论 |
|---|---|
| 严重度 | 低——跳转失败是**优雅降级**（告警 + 不跳转），不影响会话读写 |
| 是否 0.6.5 引入的回归 | **不是**。key 格式与 08-19 核查时相同，`loadThrough` 也是既有 API |
| 用户可见行为 | 长会话里点最早那几条（尤其压缩过的）会点了没反应；其余条目正常 |
