# 验证记录：加号回填只进文本、不进图片（内核 0.2.0-rc.2 接口改名）

> 2026-10-02 · 由装版思灵 1.1.6（内核 `0.2.0-rc.2`）的实机报告引出 · **已修：`0.6.12`（commit `830439b`，tag `v0.6.12`）**

## 现象

会话消息 hover tip 里的 **加号 ＋**（「一键全文 + 附件回填输入框」）在 1.1.6 上**只把文本填进输入框，图片不进去**。
用户侧观察：「原本是能将图片一并加入输入框的，现在也不行了」。文本填充正常、无报错、无提示。

## 根因：内核把两个运行时方法改了名

本插件的附件回填链路按设计文档是 `readAttachment` → `File` → `createDraftImages` → `addImages`，
其中后两个**不在 `IConversation` / `InputActions` 的类型面上**，因此是 **cast 局部接口**拿的运行时方法
（见 `docs/设计/2026-08-29-收藏功能设计.md:42` 与 `src/client/index.tsx:2058-2061` 的注释）。

内核 `0.2.0-rc.2` 里两个名字都变了：

| 本插件调（旧名） | 内核现在叫 | 内核出处 |
|---|---|---|
| `conversation.createDraftImages(files)` | **`createDrafts(sessionId, files)`** —— 还多一个 `sessionId` 参数 | `packages/client/ui-conversation/src/client/service.ts:309` |
| `inputActions.addImages(ids)` | **`addAttachments(ids): boolean`** | `packages/client/ui-conversation/src/client/contract/input.ts:180, 235` |
| `inputActions.setDraft(text)` | `setDraft(text)` —— 未变 | 同上 `:178, 233` |

本插件侧的三处调用点：`src/client/index.tsx:1389`（`addImages` 声明）、`:1393`（`createDraftImages` 声明）、
`:1678`（`createDraftImages` 调用）、`:1681`（`addImages` 调用）、`:2061`（cast 目标）。

**为什么没有报错**：`createDraftImages` 取不到时走的是既有的降级分支（`src/client/index.tsx:1656`
起的那段，「Degrades to…」），而 `addImages` 的调用点写作 `inputActions.addImages?.(ids)` —— 可选链，
方法不存在即静默跳过。两条路径都不抛错，于是表现为「文本进去了、图片没进去」。

## 修法（`0.6.12` 已实施）

1. `src/client/index.tsx:1393` 与 `:2061`：cast 目标改为 `createDrafts(sessionId, files)`
2. `:1678`：调用改为 `conversation.createDrafts(sessionId, files)`，`sessionId` 取 `props.sessionId`
3. `:1389` / `:1681`：`addImages(ids)` 改为 `addAttachments(ids)`
4. **保留降级分支**：目标方法缺席时仍退回仅文本填充
5. **降级要可见**：目前降级完全无声，用户只能靠"图片没出现"自己发现。建议在降级时给一次提示
   （复用既有 toast 通道即可），否则同类过期会在下一个内核版本上重演且无人察觉

版本号：已随修复 bump 到 `0.6.12`（commit `830439b`）。实施时按**双轨**写——新名优先、旧名兜底：声明的 peer 范围 `>=0.1.7-rc.2 <0.3.0` 横跨两代内核，只认新名会把 rc.1 那一侧也变成静默失效（`loadThrough` 早就是这个写法）。

## 判据（怎么算修好）

在实机上 hover 一条**带图**的历史消息 → 点加号 → 输入框同时出现**消息全文**与**图片缩略图**；
发送后消息里应带着那张图。只验"文本进去了"不算通过。

## 实测（2026-10-02 · 隔离实例）

在 `.ssid-iso-test` 的隔离实例（CDP 9225，只写隔离插件集 `ssid-plugins-dev`，未碰装版）上做 A/B：

| 隔离集里的 client 产物 | 点「填充到输入框」后的 composer |
|---|---|
| `0.6.11`（rc.2 上坏的那版） | `imgs: 0` —— 图不进（复现） |
| `0.6.12` 产物 | `imgs: 1, chips: 1` —— 图进 |

同一条带图消息、同一个操作，唯一变量是产物。构造场景有两个前提，一并记下：① 需要 **≥2 条带图用户消息**，否则 rail 按 `messages.length < 2` 不渲染（`src/client/index.tsx:1818`，其中 `messages` 只统计用户消息）；② 换完产物**必须重启 host**，只 reload 会继续跑旧 bundle（host 按 `rev=` 缓存）。

## 附带教训

**cast 运行时方法的写法天生会随内核升级静默过期。** 类型面没暴露的方法（内核有意或疏漏）一旦改名，
TypeScript 一声不响，运行时也只在可选链上悄悄跳过。所以每一个 cast 点都应当：

- 记在「内核升级时的核对清单」里（本插件的 cast 点集中在 `src/client/index.tsx` 末尾那段注释附近）；
- 至少配一条**可见的**失败信号，别让降级只是"少了个图"。

这件事对上游也有反馈价值：`createDrafts` 未出现在 `IConversation` 类型面上，是第三方插件不得不 cast 的直接原因。
